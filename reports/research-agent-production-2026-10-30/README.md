# Claude Agent SDK production integration

Focused release authorized by the user in ORCHESTRATOR, with ownership recorded in issue #89. The tested local implementation at `8742434` is reconciled with the current site. Source, backend and frontend deployment are separate gates; this initial record is not a live-release claim.

The existing `/api/chat` route uses Claude Agent SDK 0.2.174 when `RESEARCH_AGENT_ENABLED=1`. Six read-only tools browse/search all extracted corpus pages, follow lossless page cursors, search/read the public CRM and ask clarifying questions. Citations resolve exact text only from sources read during the investigation, retaining source exclusions and original metadata. Citation identity validation is not automatic semantic verification. The original corpus and semantic index stay in place; a separate full-page index is derived from their SQLite page text. Public CRM is packaged from committed source, not personal notes.

The internal gateway accepts only loopback requests with an ephemeral investigation token. Every model HTTP attempt, including SDK retries, structured-output calls and failures, receives a unique committed reservation in the existing production `answer-usage.sqlite` before dispatch. No dev accounting module or data is packaged. No failed reservation is refunded. The existing dated 500/day and $50 October allowance remains unchanged, reverting to 100/day and $5/month in November. Each investigation is also bounded to 12 model attempts, $3 conservative reservations and 110 seconds; it may finish below those bounds. Source search and full documents remain available when capacity runs out.

Rollback: disable `RESEARCH_AGENT_ENABLED` to restore the retained single-call answer route, or roll back the research service to deployment `d3f5457c-3aab-4ce7-a549-56c51bf52030`. Neither action resets accounting.
