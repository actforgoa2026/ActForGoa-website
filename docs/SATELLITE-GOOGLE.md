# Google services in the satellite workspace

Earth Engine is an explicit alternative imagery provider. Set `SATELLITE_IMAGERY_PROVIDER=earth-engine`, `EARTH_ENGINE_PROJECT`, and the server-only `EARTH_ENGINE_CREDENTIALS_JSON` authorized-user credential. The existing OAuth grant is limited to `earthengine.readonly`; this integration performs no exports or asset writes. Personal OAuth can be revoked or expire and then needs reconnecting. A separately provisioned service identity is a future operational improvement, not configured by this change.

Acquisitions come from `COPERNICUS/S2_SR_HARMONIZED`. Scene identifiers have an `ee-` prefix so retained CDSE rasters cannot collide with Earth Engine observations. Each request retrieves one exact scene with verified acquisition time, six scaled reflectance bands, native categorical SCL and a validity mask, on the existing snapped UTM 10 m grid. SWIR/SCL remain native 20 m measurements. Existing area limits, actor-private cache, cloud buffering, numerical comparisons and uncertainty thresholds remain in force. CDSE remains available by explicitly selecting `cdse`; no silent provider fallback occurs.

`GOOGLE_MAPS_API_KEY` belongs only on the Python API service. The authenticated, CSRF-protected `/environment` action fetches current weather and air quality at the selected area's centre, at most 50 requests (100 provider calls) per UTC day across the service. Each provider response is time- and size-bounded; one provider can fail independently. Responses are not retained with investigations. The frontend displays timestamps and Google Maps attribution and clears readings when the area/account changes. Google directions use a Maps URL. The server key is never embedded in a browser bundle.

The Google street map and submitted place searches use a separate `GOOGLE_MAPS_BROWSER_KEY` on the frontend service. `/api/map-config` intentionally returns only that website-restricted key; a missing browser key never falls back to the private server key. Restrict it to Maps JavaScript API and Places API (New), and the exact hosted origin. The Maps JavaScript loader uses origin-only authorization, so website restrictions must match the origin without a specific path. Local testing needs a temporary localhost origin restriction, removed after acceptance. Main/review deployments need their own configured browser key and allowed origin before adopting this frontend.

Place search uses the Places New library, only on submit, requesting five results and four fields within the Goa rectangle. Dated Earth Engine imagery remains a separately attributed ground overlay, with the original 25 km² selection limit, coordinate alternative, opacity control and timeline. Drawing uses map projections rather than the deprecated Drawing library. Amche GeoJSON layers retain their own source dates. Referrer policy sends only the website origin to Google. Key/configuration or network failures have an explicit retry and coordinate fallback. Google owns its map attribution controls; these remain visible during drawing.

OpenAI Decisions is an independent, existing optional classifier. It runs only when explicitly configured and there is sufficient common clear coverage. The user initially deferred OpenAI, then supplied an existing key privately and explicitly resumed activation. `OPENAI_API_KEY` and `SATELLITE_CLASSIFIER=openai-decisions` now belong only on the satellite API service. One real hosted comparison returned all seven answers from `gpt-6-luna`, with 94.11% common usable coverage. No separate Identifier credential is required. Numerical imagery evidence remains available. Combining Earth Engine pixels and Decisions does not establish model accuracy, causal conclusions, or individual-tree loss.

Validation: 140 Python satellite tests, 223 Node tests, production TypeScript/Vite build; live local Earth Engine catalogue and aligned GeoTIFF retrieval; real Google Weather/Air Quality UI results. Hosted deployment/acceptance is recorded separately in the implementation ledger and release report.
