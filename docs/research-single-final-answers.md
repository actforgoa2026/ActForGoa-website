# Single-final corpus answers

This offline candidate replaces the generated planning call with one final request using the full selected corpus evidence. It is implemented and mechanically tested, but has no fresh model acceptance or release approval. The integration coordinator owns real-provider tests and deployment. Earlier two-pass diagnostics remain historical failures or incomplete runs; their acceptance does not transfer.

The explicit configuration is `ANTHROPIC_ANSWER_PIPELINE=single_final_v1`, with `RESEARCH_CHAT_PROVIDER=anthropic`, `ANTHROPIC_CHAT_MODEL=claude-haiku-5-5`, `ANTHROPIC_CHAT_EFFORT=medium` and exactly 12,000 output tokens. The base medium setting authorizes only the fixed `single_final_high_v1` policy: one `reconstruction` request at high effort with adaptive thinking. The generic native `single_pass` allowlist remains unchanged. No retry, alternate model, repair call, web lookup or fallback is added.

## Identity and source contract

Capture version is 12; workflow is `single_final_full_evidence_v1`; `provider_call_count` is the strict integer 1; `plan_input_mode` is `no_generated_plan_empty_adapter_v1`. The complete detached spec and policy metadata are required in acceptance plans and bound into cache identity. Boolean or floating-point call counts, old versions, policies and specs fail before packet, credential, native or ledger access.

The final protocol still receives the exact canonical compatibility value `{"status":"insufficient_evidence","points":[],"units":[]}`. Its metadata includes its encoded SHA-256 and `{"plan_origin":"local_empty","generated_plan":false}`. This is an input adapter for no generated plan, not a model judgment that the corpus lacks evidence. A new object is returned for every export. Mutated fields, field order, container types or nonempty lists reject. Every nonempty model `plan_refs` rejects without editing the response. There is no invented first request, receipt, answer, model-validation event or both-wire proof.

Native retrieval and selection stay unchanged at 24,000 bytes. The final request preserves all selected question, sources, evidence, retained history and scope within 36,000 message bytes and a 4,096-byte schema. Native instruction identity and exact retained-history suffix checks run before payload observation or reservation. The transport scans the unfragmented original for credentials before exposing the baseline. A dedicated single-wire proof verifies the actual captured final body against that safe original, including source registry ownership and hashes. The historical two-wire checker still requires a real first wire.

Final prompt and schema bytes are unchanged. The standard 350-word and brief 80-word limits remain instructions, not newly invented validators. The [12-profile wire fixture](../tests/research/single-final-v12-wire-parity.json) was generated from baseline `a097e0208fc7ef4c484a884ad4579e501b721cc6` using fictional evidence, the local-empty input and HTTPX serialization, without provider calls. Current actual fake transport bytes match each v12 final body across both styles, three history variants and two scopes. This proves input parity only, not equal model answers.

Claim-local primary/source selectors, context requirements, publication/year checks, support bounds, strict JSON and deterministic paragraph assembly remain. Direct claims can still share publication attribution within the same paragraph under the existing rules. No generated plan units exist to supply inherited obligations. A correct source selector does not prove that the generated sentence preserves the source's meaning.

## Timing and accounting

The sole stage and HTTP read limit are 65 seconds; connect/write/pool remain 10 seconds. The effective deadline is still the original HTTP-entry clock plus 65 seconds, including retrieval and preparation. A request starting after 20 seconds has at most 45 seconds remaining. The former separate 45-second phase cutoff is removed. Availability is checked before and after dispatch observers, response handling, normalization and final observation, and the unchanged HTTP route checks again before cache insertion. Cancellation-suppressing transports cannot publish late output. Noncancellable native work is joined before releasing ownership, so 65 seconds is not a hard whole-HTTP completion promise. UI timeout stays 75 seconds.

The one-stage advisory is strictly typed and read-only, including when no ledger exists. It never authorizes dispatch. The unchanged atomic `reserve_stage` transaction remains the authority and rechecks capacity and UTC after locking. The historical pair helper still requires exactly two costs. There is one real receipt/send per successful answer; failed, cancelled and uncertain attempts retain their charges and cannot trigger retries.

At the existing reviewed rates, the final upper reservation is 10,624 micro-USD per case. The unchanged 71 semantic cases plus 3 distinct HTTP journeys require fresh review. At least four unspent launch attempts must remain available; this is capacity, not four mandatory calls. The conservative 78-call ceiling is 828,672 micro-USD additional. Actual execution requires a fresh exact ledger and separate coordinator authorization; these arithmetic bounds grant none.

## Retired execution assumptions and replacements

Only one phase now executes. Every active two-phase mutation/timeout/duplicate/failure parameter matrix maps its mutation to the sole final phase. The unsupported second-request wait is removed from HTTP cancellation tests. This reduces duplicate execution cases while retaining each failure mode.

Removing planning loses optional coverage guidance and inherited plan-unit requirements. The local insufficient-evidence sentinel may bias abstention. These are risks for the unchanged fresh semantic gate, not reasons to lower its expectations. Passing these tests is neither legal accuracy certification nor live readiness.
