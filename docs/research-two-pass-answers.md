# Corpus-grounded reconstruction pipeline

Implementation for review; not a statement that AI answers are enabled or accepted. The coordinator owns integration, live calls, canonical accounting and site activation. Earlier failed semantic captures remain failed. Source-first retrieval and the full 71-case final-answer review gate are unchanged.

## Explicit configuration

`ANTHROPIC_ANSWER_PIPELINE=two_pass_v12` requires `RESEARCH_CHAT_PROVIDER=anthropic`, `ANTHROPIC_CHAT_MODEL=claude-haiku-5-5`, `ANTHROPIC_CHAT_EFFORT=medium` and the existing 12,000-token output limit. Omission retains the separate `single_pass` path. There is no automatic fallback, retry, third call or different model. Existing secure key/workspace provisioning remains server-only.

The API and acceptance harness both call `backend.answer_pipeline.run_answer_pipeline`. The first call returns a bounded source-selection plan, with requested-point labels, gap codes and selector bundles. It produces no answer prose. Every unit receives strict source ownership, context and publication-label checks. Prose-only first-pass checks are explicitly inapplicable; no fabricated sentence is passed to the old answer validator. A mechanically valid empty or insufficient plan still reaches reconstruction with all evidence. An invalid or oversized plan is a pipeline failure, never a factual insufficient-evidence result.

Both stages receive the same complete prepared source records, evidence, question, retained history and request scope. Reconstruction additionally receives the exact validated but semantically untrusted `evidence_plan`. Coverage, kind and role labels are model assertions, not verified facts. Under `lossless_source_spans_v2`, eligible support strings become ordered two-item `[span_id,text]` fragments of at most 600 Unicode characters. Every original character and whitespace is retained; joining the fragments must reconstruct the exact original payload. Whitespace-only fragments inside an annotated string use `[null,text]`; null is never selectable. Original wholly empty/whitespace strings and non-string/nested metadata remain unchanged and grant no invented support. Preexisting arrays are not annotations. Whole publication labels cannot be split; a label over 600 characters is refused. Other fields remain unchanged. The actual sent bytes are checked against the registry and original payload, including source ownership and offsets.

Both stages select `{citation_id,span_id}` pairs. Neither stage supplies a quotation or field name. The server resolves each selector to its exact original citation, field and text before running the existing guards. A passage span belongs only to that passage; a source metadata span can be used only with a passage referencing that exact source record. Invalid IDs or ownership stop the answer; there is no nearest-match repair. Source-span selection does not add evidence or make a claim true.

Reconstruction cannot retrieve again or silently shorten evidence. The compact plan is capped at 8,192 UTF8 bytes; complete correction messages at 36,000 bytes and schema at 4,096. Overflow stops before reserving the second call. The original 24,000-byte first-stage bound remains. Legacy retrieval, `prepare_answer` and its native selection instructions are unchanged: the new concise instructions are a separate wire-only transformation after the original selection. A smaller prompt never selects additional evidence or restores discarded history; overflow never re-runs the trimming loop. Segmentation prefers sentence/whitespace boundaries but long conditions may span fragments; the model must select all needed support. Public support limits remain unchanged.

Each reconstructed paragraph contains claim units with mandatory `plan_refs`, its own exact passage support and required source-context support. References are distinct strict integers into the exact bound plan. Every selector from each referenced unit must occur in that claim, with no auto-addition or repair. Empty refs allow recovery from unplanned evidence; they do not justify dropping source conditions. Only after this check is the internal field removed before unchanged final native/public validation. The server joins claim text with one space and unions citations without adding connecting prose. Publication label/year acknowledgement remains paragraph-local for direct claims. A referenced unit retains all its labels in its referencing claim. The paragraph cap counts ten distinct resolved `(citation_id,field,quote)` tuples, while each plan unit and final claim permits ten selector occurrences. Existing public paragraph, text and style guards still apply. The 350-word standard and 80-word brief instructions remain generation instructions, distinct from existing mechanical limits; this revision does not silently add a word-count rejection gate. The final response retains the public citation and reader-link format. The cache contains only the reconstructed final, bound to pipeline version, both prompts/schemas/configurations and prepared evidence/history. Failed correction never returns or caches the plan.

These are mechanical guards, not an entailment judge. An exact quote can accompany a wrong claim. Authored controls deliberately preserve that failure for scope, quantity, date, table measure, missing coverage and mandatory conditions. A model correction score does not count as independent acceptance.

## Execution and accounting

Each request owns its asynchronous provider transport. Each phase has a 45-second cancellation ceiling and shares one 65-second provider/no-new-dispatch deadline measured from HTTP entry, including request-body, corpus retrieval and preparation time. Its effective deadline is the earlier of phase start plus 45 seconds and original request start plus 65 seconds; reconstruction receives only the remaining allowance. HTTPX read timeout is aligned at 45 seconds, with connect/write/pool at 10 seconds. This transport setting does not extend the shared deadline. The actual request hook checks both deadlines before capture work and after synchronous observer persistence; a known-unsent phase expiration retains the committed receipt with zero sends. Browser disconnect cancels active provider I/O, prevents the next phase and blocks final publication/cache. The existing 75-second UI timeout is unchanged.

The synchronous native corpus search cannot safely be forcibly cancelled. A cancelled request retains ownership and joins that worker before releasing its slot. It then rechecks deadline/disconnect before any provider work. This is not a hard 65-second total HTTP or native-work completion guarantee. Actual HTTP latency remains a separate live acceptance check; cancelling local I/O does not prove the provider stopped billable computation.

The shared $5/month and 100-attempt/day limits remain. Complete-pair preflight is read-only and advisory; each phase needs its own atomic `reserve_stage` receipt. Concurrent consumption can refuse reconstruction after a charged draft. Committed reservations remain after errors, cancellation, missing usage or uncertain transmission. A duplicate parent/phase receipt cannot authorize another send. UTC is checked by the ledger after its lock and again immediately before dispatch. No transaction spans provider I/O.

At the currently reviewed rates and fixed maximum bounds, draft reserves at most 9,424 micro-USD; reconstruction 10,624; a pair 20,048 ($0.020048). Actual smaller packets reserve less. Seventy-one complete pairs reserve at most 1,423,408 micro-USD and normally require 142 provider attempts, so evaluation must span UTC-day stages. These are conservative reservations, not actual invoice totals. Prices, schema/token overhead and reported usage still need the existing live checks.

The exact original-byte basis is the UTF8 content string of the unchanged original prepared final user message, serialized by `prepare_answer` as compact JSON with `ensure_ascii=False` and insertion-order keys. These checks do not dispatch. Decoded nested JSON and Unicode-escaped echoes are checked before annotation can split a secret. Unsafe baselines stop with zero new reservations/sends and no plaintext baseline capture.

At each actual request hook, the adapter decodes the safe HTTP bytes, verifies the immutable complete request digest, restores every annotated source field, and requires exact JSON types/key order and original UTF8 bytes/hash. Both phases must reconstruct to the same safely captured preparation; reconstruction independently rechecks the captured draft body too. Outer HTTP JSON escaping may vary. The first wrapper is closed to question, sources, evidence, request_scope, anchor_protocol and plan_protocol; correction adds only evidence_plan. Both generated wire schemas are checked before the first reservation. Actual final encoded messages and exact plan identity are checked before the second reservation. Later known-unsent wire failures retain the committed receipt and record zero sends, blocked before transport.
