# Corpus-grounded reconstruction pipeline

Implementation for review; not a statement that AI answers are enabled or accepted. The coordinator owns integration, live calls, canonical accounting and site activation. Earlier failed semantic captures remain failed. Source-first retrieval and the full 71-case final-answer review gate are unchanged.

## Explicit configuration

`ANTHROPIC_ANSWER_PIPELINE=two_pass_v4` requires `RESEARCH_CHAT_PROVIDER=anthropic`, `ANTHROPIC_CHAT_MODEL=claude-haiku-5-5`, `ANTHROPIC_CHAT_EFFORT=medium` and the existing 12,000-token output limit. Omission retains the separate `single_pass` path. There is no automatic fallback, retry, third call or different model. Existing secure key/workspace provisioning remains server-only.

The API and acceptance harness both call `backend.answer_pipeline.run_answer_pipeline`. The first call selects exact source spans in the paragraph-level draft shape. Resolved supports then pass the existing native/public draft guards. Invalid, refused or incomplete drafts stop. A mechanically valid insufficient-evidence draft still reaches reconstruction so supported requested content can be recovered.

Both stages receive the same complete prepared source records, evidence, question, retained history and request scope. Reconstruction additionally receives an explicitly untrusted compact draft containing only status and normalized paragraph text/citation IDs. Under `lossless_source_spans_v2`, eligible support strings become ordered two-item `[span_id,text]` fragments of at most 600 Unicode characters. Every original character and whitespace is retained; joining the fragments must reconstruct the exact original payload. Whitespace-only fragments inside an annotated string use `[null,text]`; null is never selectable. Original wholly empty/whitespace strings and non-string/nested metadata remain unchanged and grant no invented support. Preexisting arrays are not annotations. Whole publication labels cannot be split; a label over 600 characters is refused. Other fields remain unchanged. The actual sent bytes are checked against the registry and original payload, including source ownership and offsets.

Both stages select `{citation_id,span_id}` pairs. Neither stage supplies a quotation or field name. The server resolves each selector to its exact original citation, field and text before running the existing guards. A passage span belongs only to that passage; a source metadata span can be used only with a passage referencing that exact source record. Invalid IDs or ownership stop the answer; there is no nearest-match repair. Source-span selection does not add evidence or make a claim true.

Reconstruction cannot retrieve again or silently shorten evidence. The normalized compact draft is capped at 8,192 UTF8 bytes; complete correction messages at 36,000 bytes and schema at 4,096. Overflow stops before reserving the second call. The original 24,000-byte first-stage bound remains. Legacy retrieval, `prepare_answer` and its native selection instructions are unchanged: the new concise instructions are a separate wire-only transformation after the original selection. A smaller prompt never selects additional evidence or restores discarded history; overflow never re-runs the trimming loop. Segmentation prefers sentence/whitespace boundaries but long conditions may span fragments; the model must select all needed support. Public support limits remain unchanged.

Each reconstructed paragraph contains claim units, each with its own exact passage and required source-context support. The server joins claim text with one space and unions citations without adding connecting prose. Publication label/year acknowledgement remains paragraph-local; supports are deduplicated with a ten-support paragraph ceiling. Existing public paragraph, text and style guards still apply. The 350-word standard and 80-word brief instructions remain generation instructions, distinct from existing mechanical limits; this revision does not silently add a word-count rejection gate. The final response retains the public citation and reader-link format. The cache contains only the reconstructed final, bound to pipeline version, both prompts/schemas/configurations and prepared evidence/history. Failed correction never returns or caches the draft.

These are mechanical guards, not an entailment judge. An exact quote can accompany a wrong claim. Authored controls deliberately preserve that failure for scope, quantity, date, table measure, missing coverage and mandatory conditions. A model correction score does not count as independent acceptance.

## Execution and accounting

Each request owns its asynchronous provider transport. Each phase has a 30-second cancellation deadline and shares a 65-second provider/no-new-dispatch deadline measured from HTTP entry, including request-body, corpus retrieval and preparation time. Browser disconnect cancels active provider I/O, prevents the next phase and blocks final publication/cache. The existing 75-second UI timeout is unchanged.

The synchronous native corpus search cannot safely be forcibly cancelled. A cancelled request retains ownership and joins that worker before releasing its slot. It then rechecks deadline/disconnect before any provider work. This is not a hard 65-second total HTTP or native-work completion guarantee. Actual HTTP latency remains a separate live acceptance check; cancelling local I/O does not prove the provider stopped billable computation.

The shared $5/month and 100-attempt/day limits remain. Complete-pair preflight is read-only and advisory; each phase needs its own atomic `reserve_stage` receipt. Concurrent consumption can refuse reconstruction after a charged draft. Committed reservations remain after errors, cancellation, missing usage or uncertain transmission. A duplicate parent/phase receipt cannot authorize another send. UTC is checked by the ledger after its lock and again immediately before dispatch. No transaction spans provider I/O.

At the currently reviewed rates and fixed maximum bounds, draft reserves at most 9,424 micro-USD; reconstruction 10,624; a pair 20,048 ($0.020048). Actual smaller packets reserve less. Seventy-one complete pairs reserve at most 1,423,408 micro-USD and normally require 142 provider attempts, so evaluation must span UTC-day stages. These are conservative reservations, not actual invoice totals. Prices, schema/token overhead and reported usage still need the existing live checks.

## Capture v4 and frozen plans

Historical single-pass and `two_pass_v1`/`two_pass_v2`/`two_pass_v3` artifacts remain unchanged and cannot authorize this candidate. New plans must contain `pipeline: "two_pass_v4"`, the exact shared `PIPELINE_SPEC` including `anchor_protocol: "lossless_source_spans_v2"` and capture version 4, and for each UTC-day stage separate `max_cases` (equal to selected packet count) and `max_attempts` (at least twice that count, at most 100). The environment must independently select the same pipeline/model/effort/output bound. Existing exact-head, generation, ledger and execution-authorization checks still run before key loading or native access. Planning only hashes question packets.

The harness starts no new pair within 65 seconds of UTC reset. Mid-pair rollover stops before the next dispatch, retaining receipts and unrun cases. Reports cannot resume or overwrite a prior path. Every phase records exact safe outgoing bytes/hash/config, parent/phase identity, receipt and counters, state, known dispatch initiation or transmission uncertainty, available usage/stop metadata and timings. Both phases add original-baseline/actual-wire equality proofs, registry ownership/hash, input bindings, safe raw selectors and separately labelled deterministic support resolution, including partial failures. The draft records its normalized result; reconstruction adds the exact compact draft, final assembly offsets and normalized answer. Raw thinking, credentials and arbitrary error bodies are excluded. A failed capture write stops further work.

Capture v4 retains both phases' original selectors unchanged alongside separately labelled deterministic resolved citation/field/quote supports, including partial resolution before a failed selector. Registry ownership/offsets/hash, annotated payload hash and lossless original-payload equality from the actual outgoing bytes make this reproducible. A mechanically valid answer that drops a visible historical date or misstates scope remains a semantic failure; new instructions preserve visible date attribution without inferring observation dates or present validity from publication dates.

The exact original-byte basis is the UTF8 content string of the unchanged original prepared final user message, serialized by `prepare_answer` as compact JSON with `ensure_ascii=False` and insertion-order keys. It is labelled `prepared_original_payload`, not falsely described as an actual send. History and request scope have a separate immutable binding. Before baseline capture, observer notification or the first reservation, the provider-owned transport builds local synthetic requests and checks both the original unfragmented request and the exact baseline using its actual API/workspace credentials. These checks do not dispatch. Decoded nested JSON and Unicode-escaped echoes are checked before annotation can split a secret. Unsafe baselines stop with zero new reservations/sends and no plaintext baseline capture.

At each actual request hook, the adapter decodes the safe HTTP bytes, verifies the immutable complete request digest, restores every annotated source field, and requires exact JSON types/key order and original UTF8 bytes/hash. Both phases must reconstruct to the same safely captured preparation; reconstruction independently rechecks the captured draft body too. Outer HTTP JSON escaping may vary. The draft wrapper is closed to question, sources, evidence, request_scope and anchor_protocol; correction adds only draft_answer. Later known-unsent wire failures retain the committed receipt and record zero sends, blocked before transport.

Final claim/coverage review remains pending even after mechanics pass. Before enabling a testing preview, the coordinator must inspect the frozen code, review a bounded real-model diagnostic, and finish the API/conversation checks. Public activation additionally needs the complete 71-case gate, genuine ledger reconciliation, actual desktop/phone verification and public alias checks. Existing guides and source search remain independently usable.

## Reviewed instruction changes

The wire-only workflow first chooses directly requested points, reads the complete source proposition and linked conditions, selects support, and only then words the answer. It preserves mandatory design/procedure requirements, normative force and unavailable referenced details whenever a legal point is stated; an unrelated legal point may be omitted entirely. Questionable as well as contested statements require attribution. Draft table handling intentionally aligns with the correction stage: identify visible measures and limits without implying that unseen original content supplies a missing measure. Restrictions on table-fragment values remain unchanged.

[Instruction parity record](research-span-instruction-parity.json) pins all four rendered prompt hashes and the independently reviewed old/new control matrix. This is approval of the instruction design, not evidence of generated-answer accuracy. The consumed capitalization and omitted-condition failures remain negative regression evidence.

## Medium-effort candidate

`two_pass_v4` changes both phases from low to medium effort and rejects the old version or low-effort combination. The four reviewed prompt byte strings, schemas, original evidence selection, span protocol, capture format, receipts, output and timeout limits are unchanged. The parity record identifies the earlier v3 prompt review; v4 reuses those exact approved bytes. This change has no observed accuracy or latency pass yet. Fresh final-runtime outputs must satisfy the same independent acceptance gate; no old low-effort result transfers.
